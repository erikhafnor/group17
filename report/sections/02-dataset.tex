\section{Dataset}
\label{sec:dataset}

MAUDE is published as zip archives of pipe-delimited text~\cite{fda-mdr-files}. Six file
families share the key \texttt{MDR\_REPORT\_KEY}: the \emph{master} file has one record per
report, and the \emph{device}, \emph{patient}, \emph{text} (narratives), \emph{device problem}
and \emph{patient problem} files hold its children~\cite{ensign2017primer}. Lookups translate
problem codes to terms, and FDA's product classification file~\cite{fda-classification} maps a
device's three-letter product code to its name, regulatory class and medical specialty.

FDA publishes cumulative history files, current-year files, and each month an \emph{add} file
with new reports and a \emph{change} file with updated ones.
Table~\ref{tab:volumes} shows the October 2026 release.

The full history is far larger: the master history file alone holds 23.6 million reports
(6.6~GB uncompressed), and one year of narratives holds about 6 million records. Joining
families of this size, resolving versions and aggregating by product code makes the dataset a
natural fit for distributed processing.

\subsection{Understanding the source}

We profiled the files before writing any parsing code. The findings that shaped our design were:
\begin{itemize}
  \item the text is cp1252, not UTF-8;
  \item records end with CRLF, but 48 records in the master add file and 135 in the change file
        contain a bare line feed inside a field;
  \item fields are never quoted, so a \texttt{|} inside free text (2 patient records per month)
        shifts every later field;
  \item 405{,}111 of the 672{,}141 reports in the change file were also in the same month's add
        file, so updates must replace records, not be appended to them;
  \item dates come in two formats, and ages and weights are free text with units;
  \item one month of device records names 1{,}552 distinct manufacturers, 47 of them spellings
        of ``Medtronic'';
  \item FDA's file documentation no longer matches every file.
\end{itemize}

\subsection{Limitations}

MAUDE is passive surveillance. Reports can be incomplete, unverified or duplicated, and the
database has no denominator, since the number of devices in use is unknown. Our outputs
therefore describe reports, not failure rates, and the Gold tables are meant to direct
attention, not to quantify risk.
